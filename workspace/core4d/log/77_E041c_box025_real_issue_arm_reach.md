## 3. 真实问题诊断 (4 个独立 P)

| 编号 | 问题 | 视觉证据 | 根因层 |
|------|------|---------|-------|
| **P1** | **Body tracking 不准** (pelvis 站位偏) | sim 站到 box 左前角而非正前, t=1.0s 始终错 | reward weights (base_pos / root_xy 太弱) 或 ref motion 跟踪本身就难 |
| **P2** | **臂展物理限制** (G1 < 人) | sim 右手只能 wrap 角, 够不到 box 中部 | G1 实物臂展 ~63cm vs 人 ~75cm, 物理硬限制 |
| **P3** | **下半身不稳定** (深蹲 vs ref 站立) | t=1.0-1.8s 髋深屈, ref 是站立微弯 | leg tracking weight 太弱 / knee bound 缺失 |
| **P4** | **上肢被迫扭曲** (肘外翻) | t=1.8-2.5s 右肘指向画面右 ≠ ref 内扣 | P1+P2 二阶效应 (站偏+短臂 → 肘必须外翻才能伸过去) |

**没有 P0 (反关节 / 手背接触)**: 视频里手腕都是正常贴在 box 上, 不存在 wrist 翻转 180°. E041c additive mode (`0.7*pos + 0.3*ori`) 已经在 sphere 上把 E040 的反关节抑制了.

**Stability 100% 是假象**: pelvis_z > 0.5m 因为 sim 靠 box 撑着 (黄色 contact marker 在 box 角上), 不代表姿态合理.

## 4. 修正之前的错误论证链

**log 76 §5 (我写的)**:
> 3-box 是项目里 1 年来想要但一直没正确 port 的东西, sphere 物理上无法解决反关节, 3-box 是唯一物理可行的路径

**log 70 §2.4 (audit, 我引用的)**:
> 球各向同性, 物理上手心手背完全等价 → E040 视频里看到的"手背接触"是纯视觉伪装, E041 ori reward 在物理上是无效的视觉补丁

### 错在哪

(1) **历史包袱**: log 49 (E040) 确实记录了"手背接触", 我把这当成了"E041c 也有手背接触"的依据. **实际上 log 50 §E041c 自己写的是"前倾减轻, 仍有不自然帧", 没说"手背接触"**. E041c 的视觉问题已经从"手背接触"转移到"姿态扭曲", 是不同的问题.

(2) **过度推广 audit 结论**: audit log 70 §2.4 说"sphere ori reward 是视觉补丁"是**针对 E040→E041 的反关节问题**, 这个论断本身没错 (sphere 上 ori reward 不能从物理层惩罚手腕反转, 只能给 CEM 一个 wrist 朝向 prior). 但我错误外推为"E041c 实际效果差 → 必须 3-box". 视觉验证表明 E041c additive mode 在 sphere 上**已经把 E040 的反关节问题压下去了** (软性 wrist 朝向 prior 在 CEM 探索阶段就引导了正确方向, 不需要物理层硬约束).

(3) **混淆问题层次**: "反关节" (P0, 已解决) vs "姿态扭曲" (P4, 由 P1+P2 引发). 两者视觉都"难看", 但根因完全不同, 修复方法也完全不同.

### 修正后的事实

| 问题 | sphere 时代 | 3-box 时代 | 是否需要 3-box 解决? |
|------|------------|-----------|---------------------|
| E040 反关节 / 手背接触 | E041c additive **已解决** | (E060.x 因 eef_offset bug 未验证) | **不需要** — sphere ori reward 作 CEM prior 已够 |
| E041c 站位偏离 (P1) | 存在 | 同样存在 (跟 hand 无关) | 不能解决 |
| 臂展不够 (P2) | 物理硬限制 | 物理硬限制 | 不能解决 |
| 下半身不稳 (P3) | 存在 | 存在 | 不能解决 |
| 肘外翻 (P4) | P1+P2 二阶 | 同样 | 不能解决 |
| Reward 泛化 (P5, log 76) | 失败 (box023 摔) | 失败 (box023 摔) | 不能解决 |
| 跨 framework 一致性 (HDMI) | 不一致 | 一致 | 唯一独有价值 |

**3-box 的唯一独有价值是跨 framework 一致性**. 在 spider 内部解决 P0-P5 完全可以基于 sphere.
