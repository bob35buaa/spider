# E019: SBTO 渐进 Horizon 实现 (DynaRetarget 核心算法)

## Context

全面评测 (eval_metrics.py) 揭示:
- **所有 E016-E018 均失败**: obj_pos_err 最低 0.208m, 远超 DynaRetarget 成功标准 (0.10m)
- **E018 暴露 reward 冲突**: task-space reward 改善了 obj tracking (↓49%) 但恶化了动作质量 (E_Acc ↑19%, smoothness ↑26%)
- **根因确认**: SBMPC 短视性 (1.6s horizon) 是结构性瓶颈, 非 reward 可解

DynaRetarget 论文证明: SBTO (渐进 horizon) 在相同 dataset/robot 上将 SPIDER 37.9% → 74.6% success rate.

## SBTO 算法 (DynaRetarget Algorithm 2)

```
Input: μ ∈ R^{K·nu}, Σ, τ ∈ N^K (knot times), N samples, σ_min
for k = 1, ..., K-1:
    κ ← (k+1)·nu - 1   // growing number of decision variables
    while max(diag(Σ_{0:κ})) > σ_min:
        u* ← FHTO(μ_{0:κ}, Σ_{0:κ}, τ_{0:k}, N, I=1)   // one CEM iteration
    end while
end for
return u*
```

关键特性:
1. **渐进式**: 先优化 knot 0, 再 knot 0-1, 再 0-1-2... 直到全序列
2. **暖启动**: 每次增加一个 knot 时, 前面的 knots 已经接近收敛
3. **收敛判据**: 当 Σ 的最大对角元 < σ_min 时认为当前 horizon 收敛, 增加下一个 knot
4. **无 MPC 循环**: 不是 receding horizon, 而是一次性优化整条轨迹

## 实现方案

### 核心改动: `examples/run_mjwp.py` 新增 `run_sbto()` 函数

不修改现有 MPC 循环, 而是添加一个独立的 SBTO 模式函数. 通过 config 参数切换:

```python
use_sbto: bool = False     # 启用 SBTO 模式 (替代 MPC 循环)
sbto_sigma_min: float = 0.05  # 收敛阈值 (DynaRetarget 论文用 0.01-0.07)
sbto_max_iter_per_knot: int = 50  # 每个 knot increment 最大迭代次数
```

### SBTO 主循环伪代码

```python
def run_sbto(config, env, ref_data, ...):
    """SBTO: optimize full trajectory incrementally."""
    total_steps = config.max_sim_steps  # 264
    total_knots = total_steps // config.knot_steps  # 264/6 ≈ 44 (knot_dt=0.1s)
    
    # Initialize controls from reference (warm start)
    full_ctrls = ctrl_ref[:total_steps].clone()  # (total_steps, nu)
    
    for k in range(1, total_knots):
        # Growing horizon: optimize knots 0..k
        active_steps = (k + 1) * config.knot_steps  # 渐进增长
        active_ctrls = full_ctrls[:active_steps]  # (active_steps, nu)
        
        # Update config for this horizon
        config.horizon = active_steps * config.sim_dt
        config.horizon_steps = active_steps
        config = compute_noise_schedule(config)  # rebuild noise_scale for k+1 knots
        
        # Optimize until convergence
        ref_slice = get_slice(ref_data, 1, active_steps + 1)
        for iteration in range(config.sbto_max_iter_per_knot):
            active_ctrls, infos = optimize(config, env, active_ctrls, ref_slice)
            
            # Check convergence: max diagonal of effective Σ
            if infos['improvement'] < config.sbto_sigma_min:
                break
        
        # Write back optimized controls
        full_ctrls[:active_steps] = active_ctrls
        print(f"SBTO: knot {k}/{total_knots}, horizon={active_steps*config.sim_dt:.2f}s, iter={iteration+1}")
    
    # Execute final trajectory (for visualization + saving)
    execute_and_save(config, env, full_ctrls, ref_data, ...)
```

### 关键实现细节

1. **env 状态管理**: 每次 rollout 后 `load_state` 回到 t=0 (sampling.py 已有此逻辑)
2. **noise_scale 动态调整**: 用 `compute_noise_schedule` 重建, shape 随 k 增长
3. **σ_min 判据**: 用 `infos['improvement']` (已有) 代替直接计算 Σ 对角元
4. **GPU 内存**: 264 steps × 2048 samples × 58 DOF ≈ 125MB, RTX 5090 32GB 无压力
5. **执行**: SBTO 优化完毕后, 用 `step_env` 逐步执行 `full_ctrls` 并录制视频/保存 qpos

### knot_dt 选择

DynaRetarget 使用 knot_dt = 0.25s. 我们的轨迹 264 frames × 0.0167s = 4.4s:
- knot_dt = 0.1s → 44 knots (精细, 但 SBTO 循环多)
- knot_dt = 0.25s → 18 knots (DynaRetarget 原始设定)
- knot_dt = 0.4s → 11 knots (当前 MPC 设置)

推荐: **knot_dt = 0.25s** (平衡精度和运行时间)

### 运行时间估算

- 每个 knot increment: ~50 iter × (2048 samples × active_steps/sim_dt rollout) 
- 对于 k=18 (完整): 18 knots × 50 iter × 2048 × 264步 ≈ 大量 但渐进的
- 实际: DynaRetarget 报告 "~1 min per second of refined motion" on CPU
- 我们用 GPU (Warp): 预计 15-30 min 全轨迹

## 风险

| 风险 | 缓解 |
|------|------|
| SBTO 收敛慢 (>30min/run) | 降 num_samples 到 1024; 增大 σ_min 到 0.1 |
| 早期 knots 收敛后被后续 knots 破坏 | DynaRetarget 论文的 "effective horizon" 分析显示不会 |
| GPU OOM 在 full horizon rollout | 分段 rollout (前半段不存 trace) |
| σ_min 判据不准 | 备选: 固定每 knot 迭代 N 次 (不检测收敛) |
