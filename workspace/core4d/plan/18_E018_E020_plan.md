# E018-E020: DynaRetarget/Harmanoid 启发的双机器人协作搬箱优化

## Context

E017 首次实现箱子持续离地 (98% 帧), 但可视化质量差:
- **箱子漂移**: connect 约束是人工焊接, 箱子被"拖着走"而非物理抬起
- **动作 tracking 差**: 单一 qpos L2 奖励缺乏 task-space 约束
- **SBMPC 短视**: horizon=1.6s, 无法规划长期接触序列

两篇论文的核心启发:
- **DynaRetarget (SBTO, arXiv:2602.06827)**: 渐进 horizon + 丰富 task-space 奖励 (object_pos=40, torso=30, hand=5, foot=10, 速度+加速度+碰撞惩罚, success rate 74.6% vs SPIDER 37.9%)
- **Harmanoid (arXiv:2510.10206)**: interaction reward (双机器人关键点相对距离匹配) + contact reward + 课程学习

## 总体策略

**用户选择**: 一次性添加所有奖励 (代码改动最大但后续实验最灵活), 同时跑有约束和无约束两组对比.

## Phase A: E018 — Task-Space 奖励重构 + 双约束策略对比

### A.1 代码改动 (一次性完成)

#### A.1.1 `spider/config.py` — 新增 reward 字段

在 `Config` dataclass 中添加 (位置在现有 reward scale 字段附近):

```python
# Task-space rewards (DynaRetarget inspired, arXiv:2602.06827 Table II)
task_body_rew_scale: float = 0.0      # global weight for body xpos tracking
task_obj_pos_rew_scale: float = 0.0   # separate object position tracking (vs joint-space)
task_obj_rot_rew_scale: float = 0.0   # separate object orientation tracking
task_obj_vel_rew_scale: float = 0.0   # object linear velocity tracking
smooth_rew_scale: float = 0.0         # control increment penalty ||u_t - u_ref||^2

# Body tracking specification (from MJCF body names → ids resolved at startup)
task_body_names: list[str] = field(default_factory=list)  # e.g., ["pelvis", "left_hand", ...]
task_body_weights: list[float] = field(default_factory=list)  # per-body weights
# resolved at runtime in process_config
task_body_ids: list[int] = field(default_factory=list)

# Interaction reward (Harmanoid inspired)
interact_rew_scale: float = 0.0       # σ in r_int = exp(-σ * E)
interact_body_pairs: list[list[int]] = field(default_factory=list)  # pairs of body ids
```

#### A.1.2 `examples/run_mjwp.py` — 预计算参考 body 位置

在 ref_data 构建附近 (寻找 ref_data 的初始化位置), 添加:
```python
# Precompute reference body world positions for task-space tracking
if config.task_body_ids:
    body_xpos_ref = []  # (T, n_body, 3)
    for t in range(qpos_ref.shape[0]):
        mj_data_ref.qpos[:] = qpos_ref[t].cpu().numpy()
        mujoco.mj_kinematics(mj_model, mj_data_ref)
        body_xpos_ref.append(np.stack([mj_data_ref.xpos[i] for i in config.task_body_ids]))
    body_xpos_ref = torch.tensor(np.stack(body_xpos_ref), device=config.device)
    ref_data["body_xpos_ref"] = body_xpos_ref
```

需要在 `get_slice` 中也对应切片, 并在 `ref_slice` tuple 中传入新字段.

#### A.1.3 `spider/simulators/mjwp.py` — `get_reward` 重构

修改 `get_reward` 函数, 在原有 qpos_rew/qvel_rew/contact_rew 基础上添加:

```python
# Task-space body tracking
task_body_rew = 0.0
if config.task_body_rew_scale > 0.0 and config.task_body_ids:
    xpos_sim = wp.to_torch(env.data_wp.xpos)  # (N, nbody, 3)
    body_xpos_ref = ref[5]  # newly added in ref tuple
    body_pos_sim = xpos_sim[:, config.task_body_ids]  # (N, K, 3)
    body_weights = torch.tensor(config.task_body_weights, device=config.device)
    err = ((body_pos_sim - body_xpos_ref.unsqueeze(0)) ** 2).sum(dim=-1)  # (N, K)
    task_body_rew = -config.task_body_rew_scale * (err * body_weights).sum(dim=1)

# Task-space object tracking (high weight, separate from joint-space)
task_obj_rew = 0.0
if config.task_obj_pos_rew_scale > 0.0 and config.embodiment_type == "dual_humanoid_object":
    obj_pos_sim = qpos_sim[:, -7:-4]
    obj_pos_ref_t = qpos_ref[-7:-4].unsqueeze(0)
    pos_err = ((obj_pos_sim - obj_pos_ref_t) ** 2).sum(dim=-1)
    task_obj_rew = -config.task_obj_pos_rew_scale * pos_err
    # similarly add rot_err with quat_sub if task_obj_rot_rew_scale > 0

# Interaction reward (Harmanoid)
interact_rew = 0.0
if config.interact_rew_scale > 0.0 and config.interact_body_pairs:
    xpos_sim = wp.to_torch(env.data_wp.xpos)
    body_xpos_ref = ref[5]
    pair_err = 0.0
    for (i, j) in config.interact_body_pairs:
        delta_sim = xpos_sim[:, i] - xpos_sim[:, j]
        delta_ref = body_xpos_ref[i_idx] - body_xpos_ref[j_idx]  # need index mapping
        pair_err += ((delta_sim - delta_ref) ** 2).sum(dim=-1)
    interact_rew = config.interact_rew_scale * torch.exp(-pair_err)

# Smoothness penalty (passed prev_ctrl through ref tuple or env state)
smooth_rew = 0.0  # implementation requires tracking prev ctrl, defer to first iter

reward = qpos_rew + qvel_rew + contact_rew + task_body_rew + task_obj_rew + interact_rew
```

## 验证方法

每个 run:
1. **运行**: `uv run examples/run_mjwp.py +override=core4d_box025_e018_connect viewer=none save_video=true`
2. **可视化**:
   - MP4 视频检查: 箱子物理跟随 vs 漂移, 动作流畅 vs 抖动
   - 关键帧渲染 (MPC 0/3/5/8/10): 类似 E017-d 的 PNG 对比
3. **量化指标** (写入分析脚本 `workspace/core4d/scripts/analyze_e018.py`):
   - obj_pos_error 序列 (vs ref)
   - body MPJPE (per-body, vs ref)
   - 双机器人间距偏差
   - 控制加速度 (smoothness)
   - 接触力 (mocap rendered, 如有)
4. **对比基准**: E017-d (best connect run), Reference trajectory

## 成功标准

| Claim | 阈值 | 来源 |
|-------|------|------|
| C1: object tracking | obj_pos_error < 0.10m mean | DynaRetarget standard |
| C2: body tracking | global MPJPE < 0.15m | DynaRetarget |
| C3: 平滑度 | acc 减半 vs E017-d | 视觉/抖动 |
| C4: 视频质量 | 箱子无漂移, 动作自然 | 主观 |
| C5: 双机器人协调 | 间距偏差 < 0.05m | Harmanoid 启发 |

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| body_xpos_ref 预计算慢 (264 帧 × FK) | 一次性, 启动时计算 |
| 新 reward 数量级失衡导致单项 dominate | 用 DynaRetarget 论文权重作起点, 必要时按数量级缩放 |
| Interaction reward index 映射复杂 | 显式在 yaml 中写 body name, process_config 解析 |
| 无约束情况下箱子直接落地 | E018-noconnect 作为对照, 不强求成功 |
| GPU 显存 (新增 body_xpos_ref tensor) | 264×~12×3 float32 = 38KB, 可忽略 |
