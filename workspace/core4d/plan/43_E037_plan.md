# E037: Contact Mask-Gated Reward — 恢复 Contact 质量

## Context

E036 通过关闭 `hand_approach_rew` 实现了 MPKPE=1.4cm 的突破性 body tracking，但 Contact<10cm 从 94.8% 暴跌到 7%（desk005）。原因明确：没有任何 reward 激励手靠近物体。

E037 的目标：用 HDMI 风格的 **contact mask 门控** reward 恢复 contact，同时保持 MPKPE<5cm 和 Stability>90%。

## HDMI 参考设计

HDMI 的 `rew_contact` 公式 (hdmi.py:1095-1117)：
```
pos_rew = exp(-dist / eef_pos_sigma)           # sigma=0.3m
force_factor = exp(-frc_thres / frc_sigma)     # ≈0.778 (constant)
rew_contact = mean_e( pos_rew * force_factor * in_range * gain + (1 - in_range) )
```
- **mask=1** (contact frame): reward ∈ [0, gain*0.778] ≈ [0, 3.89]
- **mask=0** (non-contact): reward = 1.0 (constant, no gradient → CEM ignores contact)

## 方案: 复用现有 approach_mask + 新 reward term

### 关键设计决策

1. **复用已有的 `approach_mask_t`**（run_mjwp.py:479-497）作为 contact mask
   - 已经检测 ref 中手何时在物体 0.3m 内
   - 通过 ref_data tuple 的第 7 个元素 (`ref[6]`) 传入 get_reward
   - 无需新增预计算逻辑

2. **reward 公式对齐 HDMI**（正值 exp-kernel，非负值惩罚）：
   ```python
   # 当 mask=1: rew = gain * exp(-dist / sigma)  → 手越近越大
   # 当 mask=0: rew = gain (constant)            → CEM 无梯度
   contact_mask_rew = mask * gain * exp(-dist/sigma) + (1 - mask) * gain
   ```
   注意：HDMI 用 `1.0` 作为 non-contact baseline，但我们用 `gain` 使得 non-contact 帧的 reward 等于 contact 帧的最大值。这样 CEM 不会偏好 contact 帧或 non-contact 帧。

3. **使用 per-hand 距离** (与 hand_approach 相同的 box-SDF)：
   - 复用已有的距离计算逻辑 (mjwp.py:656-669)
   - 取 min over hands（reward best hand）

4. **Config-driven**：所有参数通过 YAML 控制，不改动 config.py 默认值

### Reward Budget 分析

| Component | Max | E036 | E037 (预期) |
|-----------|-----|------|-------------|
| local_frame_rew (body tracking) | 3.5 | 3.5 | 3.5 |
| task_obj_rew | ≤0 (penalty) | penalty | penalty |
| contact_mask_rew (NEW) | 0 | — | **gain** (e.g. 2.0) |

**关键**：gain 必须 < body tracking max (3.5)，否则重蹈 E035 覆辙。
建议 gain=2.0 → contact max=2.0 < tracking max=3.5 → body tracking 仍是 CEM 的主要目标。

## 改动文件

### 1. `spider/config.py` — 添加 3 个新字段

在 `hand_approach_contact_threshold` 之后添加：
```python
# E037: contact mask-gated reward (HDMI-style)
contact_mask_rew_scale: float = 0.0  # gain; 0.0 = disabled
contact_mask_rew_sigma: float = 0.3  # exp kernel bandwidth (meters), HDMI default
contact_mask_use_approach: bool = True  # reuse approach_mask as contact gate
```

### 2. `spider/simulators/mjwp.py` — 新 reward term (~20行)

在 `hand_approach_rew` 块之后、`reward = ...` 汇总之前，添加：
```python
# E037: contact mask-gated reward — HDMI-style proximity with mask gate
contact_mask_rew = torch.zeros(N, device=config.device)
if config.contact_mask_rew_scale > 0.0 and config.hand_approach_body_ids:
    obj_body_id = mujoco.mj_name2id(env.model_cpu, mujoco.mjtObj.mjOBJ_BODY, "object")
    if obj_body_id != -1 and config.hand_approach_obj_half_extents:
        xpos_sim = wp.to_torch(env.data_wp.xpos)  # (N, nbody, 3)
        hand_pos = xpos_sim[:, config.hand_approach_body_ids]  # (N, K, 3)
        obj_pos = xpos_sim[:, obj_body_id:obj_body_id + 1]  # (N, 1, 3)
        half_ext = torch.tensor(config.hand_approach_obj_half_extents, device=config.device, dtype=hand_pos.dtype)
        delta = torch.abs(hand_pos - obj_pos)
        surface_dist = torch.clamp(delta - half_ext, min=0.0)
        dist_per_hand = surface_dist.norm(dim=-1)  # (N, K)
        min_dist = dist_per_hand.min(dim=1).values  # (N,)
        # HDMI-style: mask=1 → exp proximity; mask=0 → constant (no gradient)
        gain = config.contact_mask_rew_scale
        mask = approach_mask_val  # scalar or (N,) from ref[6], already per-timestep
        proximity = gain * torch.exp(-min_dist / config.contact_mask_rew_sigma)
        contact_mask_rew = mask * proximity + (1.0 - mask) * gain
```

然后修改 reward 汇总行：
```python
reward = qpos_rew + qvel_rew + contact_rew + task_body_rew + task_obj_rew + interact_rew + hand_approach_rew + contact_mask_rew
```

### 3. `examples/config/override/core4d_e037.yaml` — 新配置

基于 core4d_e036.yaml，添加：
```yaml
# E037: contact mask-gated reward
contact_mask_rew_scale: 2.0   # gain (< tracking max 3.5)
contact_mask_rew_sigma: 0.3   # HDMI default bandwidth
contact_mask_use_approach: true
# Keep approach mask precomputation active
hand_approach_contact_threshold: 0.3  # ref hand within 30cm = contact frame
```

确保 `hand_approach_rew_scale: 0.0` 保持不变（不重新开启旧 reward）。

## 预计算依赖

approach_mask 的预计算（run_mjwp.py:479-497）需要 `hand_approach_body_ids` 非空才会执行。当前 E036 config 中 `hand_approach_body_names` 已配置，所以 `hand_approach_body_ids` 会在 `process_config` 中被解析。

**关键修正**：E036 中 `hand_approach_contact_threshold=100.0`（100m）→ 所有帧的 mask 都=1.0（永远激活）。E037 必须将其改为 `0.3` 才能获得真正的 mask 门控。这个阈值控制 "ref 中手距物体多近算 contact 帧"。

预计算条件是 `config.hand_approach_body_ids and config.hand_approach_contact_threshold < float("inf")`。E037 设 `threshold=0.3` 满足此条件 → approach_mask 自动预计算。无需改动 run_mjwp.py。

## 风险

1. **gain=2.0 可能仍不够**: contact 帧中 proximity reward 需要手 <30cm 才有显著 reward。如果 ref 中手在 30cm 外，mask=0 → 无激励。
2. **approach_mask threshold=0.3m 可能太严**: 只有 ref 手在 30cm 内的帧才激活 contact reward。若 ref 本身手距物体较远（如 desk005 行走阶段），mask 大部分为 0。
3. **gain 太大会退化**: 如果 gain≥3.5，contact reward 会超过 tracking → 重蹈 E035。
