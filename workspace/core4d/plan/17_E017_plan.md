# E017: 双机器人协作搬箱优化

## Context

E016-a 首次实现双 G1 Gibbs CEM (nq=79, obj_z=0.488), 但箱子仍是被推/翻而非抬起。根因:
1. **无手-箱约束**: CEM 靠碰撞采样产生接触力 → 概率极低
2. **CEM timing 过粗**: dual 配置继承 default (ctrl_dt=0.4, 4 knots), 而单机器人用 0.1 (8 knots)
3. **contact_rew=0**: 手与箱无引导

## 方案: Connect (Weld) 约束 + CEM 参数调优

### 核心思路

E010 (单机器人) 证明: 把手焊接到箱面 → CEM 只优化身体 → 箱子自动跟随手。
→ 扩展到双机器人: 4 个 connect 约束 (每机器人两只手) → 双机器人协作搬箱

### 实验矩阵

| Run | 方法 | 关键变化 | 预期效果 |
|-----|------|---------|---------|
| E017-a | 4-connect + body reward | 4 手焊接到箱 + ctrl_dt=0.2 | **最高** — 箱物理附着 |
| E017-b | 2-connect (每机器人1手) | 减少过约束风险 | 高 — 更简单稳定 |
| E017-c | CEM-only 参数调优 | 细 timing + contact_rew + 更多迭代 | 中 — 无约束对照 |
| E017-d | 最佳 connect + 最佳 CEM | 组合最优 | **最高组合** |

## 实施步骤

### Step 1: 生成 `scene_dual_robot_connect.xml`

基于 `scene_dual_robot.xml`, 添加:

```xml
<!-- Object body 内添加 4 个锚点子体 -->
<body name="obj_contact_r1_left"  pos="{FK computed, ~+0.305 ±y 0}">
  <site name="obj_connect_site_r1_left" size="0.02" rgba="0 1 0 0.5"/>
</body>
<!-- ... 共 4 个 -->

<!-- equality section -->
<equality>
  <connect name="r1_hand_obj_left"
    body1="left_wrist_yaw_link" body2="obj_contact_r1_left"
    anchor="0.08 0 0" solref="-500 -50" solimp="0.95 0.99 0.001 0.5 2"/>
  <connect name="r1_hand_obj_right"
    body1="right_wrist_yaw_link" body2="obj_contact_r1_right"
    anchor="0.08 0 0" solref="-500 -50" solimp="0.95 0.99 0.001 0.5 2"/>
  <connect name="r2_hand_obj_left"
    body1="r2_left_wrist_yaw_link" body2="obj_contact_r2_left"
    anchor="0.08 0 0" solref="-500 -50" solimp="0.95 0.99 0.001 0.5 2"/>
  <connect name="r2_hand_obj_right"
    body1="r2_right_wrist_yaw_link" body2="obj_contact_r2_right"
    anchor="0.08 0 0" solref="-500 -50" solimp="0.95 0.99 0.001 0.5 2"/>
</equality>
```

**锚点位置计算**: 用 `trajectory_kinematic_dual.npz` 的 FK → 手掌在 object local frame 的中位数坐标。R1 从 -x 侧接近, R2 从 +x 侧。

**solref="-500 -50"** (比单机器人 E010 的 -1000 -100 更柔): 减少 4 约束过约束 (12 constraint eqs vs 6 DOF) 的不稳定性。

关键文件:
- 模板: `workspace/core4d/scripts/generate_scene_connect.py` (复用 `compute_contact_local` 逻辑)
- 场景: `example_datasets/.../dual_humanoid_object/box025_person1/scene_dual_robot.xml`
- R2 body 前缀: `r2_left_wrist_yaw_link`, `r2_right_wrist_yaw_link`

### Step 2: 创建 YAML 配置

`examples/config/override/core4d_box025_e017.yaml`:
```yaml
embodiment_type: dual_humanoid_object
scene_name: scene_dual_robot_connect
# CEM 细化 timing (从 4 knots → 10 knots)
ctrl_dt: 0.2
knot_dt: 0.2
horizon: 2.0
# 奖励: body 稳定 + 中等 object 跟踪
base_pos_rew_scale: 5.0
pos_rew_scale: 2.0
# CEM 精度
temperature: 0.15
max_num_iterations: 24
gibbs_sampling: true
```

### Step 3: 更新 task_info.json

`dual_humanoid_object/box025_person1/task_info.json`:
```json
{"ref_dt": 0.033333, "contact_site_ids": [11, 15, 28, 32]}
```
(4 手掌 contact sites: R1 left/right + R2 left/right)

### Step 4: 运行实验矩阵

```bash
# E017-a: 4-connect, body-focused
uv run examples/run_mjwp.py +override=core4d_box025_e017 \
    scene_name=scene_dual_robot_connect pos_rew_scale=2.0 contact_rew_scale=0.0

# E017-b: 2-connect (scene_dual_robot_connect2)
uv run examples/run_mjwp.py +override=core4d_box025_e017 \
    scene_name=scene_dual_robot_connect2 pos_rew_scale=2.0

# E017-c: CEM-only, 细 timing + contact_rew
uv run examples/run_mjwp.py +override=core4d_box025_e017 \
    scene_name=scene_dual_robot pos_rew_scale=2.0 contact_rew_scale=1.0

# E017-d: 最佳 connect + 最强 object 跟踪
uv run examples/run_mjwp.py +override=core4d_box025_e017 \
    scene_name=scene_dual_robot_connect pos_rew_scale=3.0
```

### Step 5: 可视化验证 + 日志

每个 run:
1. MuJoCo render 关键帧 (MPC 0/2/3/5/10)
2. 对比 sim vs ref
3. 量化: obj_z per MPC, pelvis_min, 持续离地帧数

## Claims (成功标准)

| Claim | 阈值 | 说明 |
|-------|------|------|
| C1: 箱子离地 | obj_z > 0.40m ≥ 3 MPC steps | 持续抬升, 非瞬间翻转 |
| C2: 双机器人稳定 | pelvis1/2_min ≥ 0.50m | 都不摔倒 |
| C3: 接近参考 | obj_z_max > 0.50m (>94% ref) | 高质量跟踪 |
| C4: 视频确认 | 协作抬起而非推/翻 | 视觉验证 |

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 4 约束过约束 → 求解器不稳定 | 用柔 solref (-500 -50); E017-b 只用 2 约束 |
| 锚点冲突 (两机器人手在同一点) | Y/Z 偏移: R1 在 +y, R2 在 -y |
| 质量过大 (5kg) | 可选: 降到 2kg 测试 |
| ctrl_dt=0.2 → 运行时间翻倍 | 可接受 (~400s per run) |
