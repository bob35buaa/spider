## 1. 引言

### 1.1 单人物理重定向的成熟与双人协作的空白

近一年来，物理一致的动作重定向（physics-informed retargeting）在**单人**操作和**单 humanoid**全身动作场景上已经趋于稳定可用。代表性方法包括 SPIDER（Pan et al. 2026）—— 基于 GPU 并行 CEM + virtual contact guidance，以及 DynaRetarget（Dhedin et al. 2026）—— 渐进 horizon 的轨迹优化。这两类方法都把"机器人手 + 单个被操纵物体"作为基本单位，验证集也以 OMOMO、ARCTIC 类单人 manipulation 为主（详见 `paper_notes/01_E001_literature_synthesis.md:9-51`）。

但当任务变成**单 G1 humanoid + 大物体 + 双人协作**（CORE4D 类）时，上述框架退化。本工作区的 E002 提供了直接证据：在 CORE4D 的 `box025_p2`、`box023_p2` 两个典型 case 上，把原 `workspace/core4d` E081 baseline 的 `scene_act` actuator 关闭、改成真 freejoint object 后，main 的物体追踪误差从 E081 的 `0.143/0.271m` 一下退化到 `0.703/1.356m`，guard 退化到 `0.830/1.488m`，而 hand contact 仍维持在 `89.6%`、`72.0%`、leg interference 为 `0%`（`log/02:42-43`）。换句话说，CEM 仍能找到"手贴箱"的接触解，但**单 humanoid 不可能在真物理下接管原本由双人共同承担的支撑力矩**，结果是物体留在地上或翻倒。E081 之所以"看起来 work"是因为它隐式依赖 6-DoF object actuator 把物体当机械手臂被拉走（`docs/01_direction_review_2026-05-18.md:14`），并非真物理搬运。

我们的工作正是攻这块空白：**坚持真 freejoint object（`nq_obj=7`，无 object actuator），用单 G1 + 虚拟 partner 把 CORE4D 双人协作 demo 重定向成物理一致轨迹**，并把 object 端跟踪精度做到接近甚至超过 E081 的 actuator-guided baseline。[基于 `log/02:38-50`、`docs/01_direction_review_2026-05-18.md:12-15`]

### 1.2 研究问题与贡献摘要

**Research Question**：能否在不依赖 `scene_act` 6-DoF object actuator 的前提下（即 true freejoint），用单 G1 humanoid + 虚拟 partner，对 CORE4D 双人协作数据做物理一致的动力学重定向，并保持 object 跟踪精度与 E081 单人 actuator-guided baseline 同级？

我们的贡献按 §4 / §5 展开：

1. 把 SPIDER 从单人 manipulation 扩展到 CORE4D 双人协作，全过程坚持 true-freejoint object，不退到 actuator 路线（E002）。
2. 从 E004 到 E012 七轮虚拟力 sweep（COM gravity、spring、hold-contact、dual-point、contact pad）系统地证伪 "spring/force coupling 范式"，并给出 spring time constant `τ=√(m/k)` 的物理诊断 —— 表明 force 范式在 freejoint 下存在结构性 xy lag 上限。
3. **COLA-B soft-weld（核心贡献）**：把 partner-object 耦合从 force 换成 position constraint，用 kinematic support body + MuJoCo `weld` equality 配上 soft `solref/solimp`，在 E014 上首次让真 freejoint object 跟踪降到 `0.056/0.087m`，与 E081 actuator-guided baseline `0.143/0.271m` 相比直接好出 ~2×（`log/14:69-74`）。
4. **Canonical Support Proxy Anchor**：把 E014 中人工挑选的 anchor 自动化为 `face center + 0.62·half_z` 规则，在 E018 两个 GT case 上 anchor dist `≤1.17cm`、在 E018b 13/13 case 上全部 anchor pass（`log/18:51-56`、`log/19:38-54`）。
5. **Paper-aligned 分层评测协议**：把验收口径拆成 anchor gate / object-side（SPIDER + DynaRetarget + transport）/ robot-side（OmniRetarget contact preservation + deep penetration + fall）/ visual stability 四层，明确指出 *object-only success ≠ 完整 retargeting 成功*（`log/19:43-50`）。

## 2. 相关工作

### 2.1 物理一致重定向

**SPIDER** (Pan et al. 2026) 是本工作的基础框架：GPU 并行的 sampling-based MPC（CEM），cost 以 object position 和 hand contact 为主，并通过 *virtual contact guidance* 在采样早期"粘住"参考的 hand-object 相对位姿来扩大可行域。SPIDER 在 OMOMO 类单人 manipulation 上稳定 work，但论文未触及双人协作（`paper_notes/01:9-24`）。**DynaRetarget** (Dhedin et al. 2026) 走另一条路：用 sequential trajectory optimization (SBTO) 把短视 MPC 升级为渐进式长 horizon 优化。SBTO 在 long-horizon 接触切换上更稳，但 "早期错一步、后续不可恢复" 的失败模式仍然存在，特别是参考接触不可靠时（`paper_notes/01:33-51`）。

### 2.2 运动学重定向

**OmniRetarget**（Yang et al. 2025）用 interaction-mesh Laplacian + SOCP 做硬约束运动学重定向。我们在 `holosoma/workspace/v1/` 对 CORE4D 做了 OmniRetarget 适配，作为本 pipeline 的运动学初始化与 reference 来源（详见 §3.2，原文 `holosoma/workspace/v1/README.md:8-34`）。OmniRetarget 自身对**双人**复杂几何 (chair/desk/board) 的可行性较差（求解器频繁 infeasible，成功率仅 45.8%），需要约束松弛 + 自适应回退才能拉到 100%（`README.md:50-70`），更不具备物理一致性。

### 2.3 双人 / 协作控制

**COLA**（Du et al. 2025）是本工作方法论的直接来源：它指出协作搬运里不能直接在 object COM 上施加 ref-tracking force，而应该让 partner 体（support body）通过 6-DoF joint 耦合到 object（`paper_notes/02_E005_du2025_cola_virtual_force_analysis.md`）。这个关键 *position constraint 而非 force* 的洞察直接驱动了我们 E014 的方法设计。**It Takes Two / Harmanoid** (Liu et al. 2025) 强调双人协作的策略必须把 partner 几何、接触和相对 root pose 纳入观测和 reward，避免单人化（`paper_notes/01:54-74`）。这与我们坚持引入虚拟 partner 而不是把 single G1 单独优化的设计选择一致。

## 3. 数据与运动学预处理

### 3.1 CORE4D 数据特性

CORE4D 是真实双人 mocap，每个 demo 包含 person1/person2 各自完整的 SMPL-X + 6-DoF 物体轨迹。我们选用 6 类物体覆盖整个 pipeline：chair/desk/board/box/bucket/stick。box 类最长边在 0.4-1.0m，明显超出单 G1 末端可达工作空间（详见 `holosoma/workspace/v1/README.md:107-119` 的统计），这也是单人化策略失败的几何根因之一。接触语义复杂：手腕、前臂、躯干都可能介入，且双人接触模式（同侧/对侧）随物体形状变化。

### 3.2 基于 OmniRetarget 的 CORE4D 适配（Phase 4a-4d）

我们在 `holosoma/workspace/v1/` 完成了 CORE4D → OmniRetarget 风格 `(T, nq)` 运动学轨迹的整套适配，作为下游动力学 pipeline 的初始化与 reference。关键四步：

1. **坐标系对齐**：CORE4D Y-up → OmniRetarget Z-up（`convert_core4d_to_omniretarget.py:13-50`）。
2. **约束松弛与自适应回退**：四级 fallback（hard → 松弛穿透 → 松弛穿透 + 脚步 → 全面松弛），把 object_interaction 成功率从 45.8% 拉到 100%（`README.md:50-70`）。
3. **高度门控接触检测**：`contact = (|v_xy|<v_thresh) ∧ (z_foot<z_min+0.02)` + 3 帧中值滤波 + 接触帧 `z_foot=z_ref` 锁定（`README.md:77-85`）。
4. **显式手-物接触保持代价**：在物体坐标系下计算手腕-物体距离，软代价 `C_contact = w·Σmax(0, ‖p_wrist - p_obj‖_obj - d_ref)`（`README.md:88-96`）。

凹形物体（chair 类）额外引入自适应点云采样（凹度 γ>0.3 时点数 ×3）和穿透容差收紧。最终输出 OmniRetarget 风格 `(T, nq)` 轨迹，下游 spider 物理 pipeline 用它做 CEM 初始化、`qpos_ref` 与 reward 计算。[基于 `holosoma/workspace/v1/README.md:38-130`]

## 4. 方法

### 4.1 问题设定

我们把 CORE4D 双人协作动力学重定向形式化为：在真 freejoint object（`nq_obj=7`）的 MuJoCo Warp 场景中，对单 G1 humanoid（`nu=29`）和一个虚拟 partner（不消耗 actuator，但提供 object 端的支撑约束），用 sampling-based MPC（CEM）找到 robot 关节 ctrl 序列，使 sim object 轨迹追踪 mocap reference。具体：每个 case 的 model 维度严格 `(nq, nv, nu) = (43, 41, 29)`（E002 验证，`log/02:42`），`contact_guidance=false`，object actuator id 列表为空 —— 任何回退到 `scene_act` actuator-guided object 都被自动维度检查 reject（E002 同时加固 `qpos-as-ctrl` 防御，`log/02:74-91`）。

### 4.2 为什么 spring/force coupling 不够 —— 结构性 lag 诊断

E004 至 E012 共七轮 sweep，把 "外部协作力" 这条范式的各种形态都穷尽了：COM-level 竖直重力补偿（E004）、support-site 等效 wrench（E005）、support-body proxy spring（E006）、proxy 时基修正 + 限速放宽（E007、E008）、robot-side hold-contact 闭环（E009）、mocap contact pad（E010）、COM/单点 soft tether 诊断（E011）、dual-point partner pose closure（E012）。所有变体都保持真 freejoint object（`num_freejoint_parity_ok` 全过），但 main 始终未到达 E081 transport gate：E008 best `box025_ypos_k20_vmax2` obj `0.363/0.684m`、xy ratio `0.724`、rot `13.6°`；E011 best `box025_com_k100` obj `0.340/0.673m`、xy `0.905`、rot `3.5°`（`EXPERIMENT_TRACKER.md:50-54`）。E011 最好成绩仍是 E081 的 2.4 倍，且任何把 spring k 提高的尝试都触发 robot 手脱开（E009 hand 86%→75%）或 MJWarp solver 数值不稳（E012/E015 部分 case）。

这不是工程参数没调好，而是范式的结构性问题。把弹簧-质量系统的时间常数代入：`τ = √(m/k)`。box025 mass≈5 kg、spring k=100 N/m 时 `τ ≈ 0.22s`；mocap ref 平均搬运速度 0.4 m/s，稳态滞后量直接得 `v·τ ≈ 0.09m`，加速段峰值落到 0.4-0.7m —— 与 E011 实测 `obj_max=0.673m` 严格吻合。要把 lag 压到 5 cm 量级，至少要 `k ≥ 320 N/m`，但那一点正好踩在 robot 手脱开和数值发散的双重边界上（详细推导见 `docs/01_direction_review_2026-05-18.md:83-105`）。

结论：**只要 partner-object 之间是"力反馈"耦合，xy lag 就有数学下限，再怎么调参也越不过去**。要消除 lag，必须把耦合从 force 换成 position constraint。

[图 2：E011 obj-position vs time，sim 与 ref 对比，标注 spring lag 区域]

### 4.3 COLA-B：kinematic support + soft weld 位置约束（核心贡献）

E014 实现了上一节结论的最小验证形态。核心思想是把 partner-object coupling 从 *force* 切换为 *position constraint*：在 scene 里增加一个 *kinematic* support body（每步从 person2 hand mocap pose 直接 set，不进入 nq）、在它和 object 之间挂一个 MuJoCo `weld` equality，并通过 *soft* `solref="0.02 1"` / `solimp="0.95 0.99 0.001"` 让它表现为带 stiffness/damping 的 6-DoF joint。Anchor 设在 object 表面而非 COM（确保不引入 direct wrench、不构成 oracle）。整个改动只动 scene XML 与 partner 数据通道，CEM、reward、`nu=29`、`nq_obj=7` 与所有 robot-side 配置完全保留（`log/14:104-110`）。

E014 跑了 6 条 full（4 main + 2 guard），结果如下：6/6 `freejoint_parity_ok`、6/6 `anchor_not_com_oracle`、6/6 `no_direct_wrench`；4/4 main 通过 E013 oracle 划出的 soft target（obj `≤0.193/0.371m`、hand `≥73.6%`、floor `≤69.5%`、leg `≤12.5%`）；2/2 guard stable。**最佳 main `t02` obj `0.056/0.087m`、hand `86.7%`、floor `51.4%`、leg `0%`、xy ratio `0.999`、rot `2.2°`、support gap mean/max `0.060/0.098m`**（`log/14:69-74`）。

需要强调两点诚实定位。第一，**E081 baseline 用的是 6-DoF object actuator + contact guidance（`nq_obj=6`、slide+euler），object 不受真实物理约束**；E014 是首次在**更严格的 true-freejoint 设定**（`nq_obj=7`、object 自由刚体、无 actuator）下，让 object 跟踪精度达到甚至超过 E081 数字。直接拿 E014 的 0.056m 跟 E081 的 0.143m 比，不是同条件比较，而是 *更难任务上 still better*。第二，4 条 main 完全 lag-free、leg-obj 0%、rot ≤2.2°、push-vs-carry gate 全过，说明 COLA-B 不靠"腿推 + 旋转 shortcut" 拿分，这是和 E006/E011 关键的质量差别。

### 4.4 Canonical Support Proxy Anchor

E014 的 anchor 是手工 per-case 设置的（`box025_p2: [0, 0.38, 0.30]`、`box023_p2: [0.16, 0, 0.10]`），不能直接泛化。E016 第一次尝试自动化时用了 `mask_active_ref_palm_centroid_surface_clamp` 策略 —— 即用 partner 手掌接触点 median 作为 anchor —— 在 `box023_p2` 上出现 face 错配：mocap GT 落在物体 `+X` 面，但 mask centroid 落到了 `+Y` 面，导致 contact preservation 下降（`log/17`）。

E018 提出 *canonical face center + upper support band* 规则：先用 E017 contact mask audit 判定 dominant face，再固定 anchor 为该 face 的几何 center 沿 face normal 偏向上方 `0.62·half_z`：

```
if face is ±X: anchor = [±half_x, 0, 0.62·half_z]
if face is ±Y: anchor = [0, ±half_y, 0.62·half_z]
```

E018 两个 GT case 全过：`box023_p2` canonical anchor `[0.1531, 0, 0.1095]` vs E014 GT `[0.16, 0, 0.10]`，dist **1.17 cm**；`box025_p2` canonical `[0, 0.3778, 0.2909]` vs E014 GT `[0, 0.38, 0.30]`，dist **0.94 cm**。两个 case 的 object tracking 与 E014 `t02` 几乎逐位对齐：`box023_p2` obj `0.0425/0.0793m`（E014 `0.0426/0.0800m`）、`box025_p2` obj `0.0562/0.0871m`（E014 `0.0562/0.0868m`）（`log/18:51-86`）。E018b 把同样规则扩展到 13 个 case，全部 13/13 通过 canonical anchor gate（`log/19:38`）。这条规则**首次把 E014 的人工 proxy 自动化、且在 GT case 上保持原始语义**。

[图 5：E016 mask-derived anchor vs E018 canonical anchor，在 box023 / box025 上的位置对比]

### 4.5 分层评测协议

我们在 E016 / E018 / E018b 上确立的评测口径分为四层，每层有独立的 pass gate：

1. **Anchor gate**：`canonical_anchor_pass`（E018b 规则一致性）+ `gt_anchor_pass`（与 E014 GT 距离 < 2 cm）。
2. **Object-side**：SPIDER paper Table 4 风格的 Epos / Erot 阈值、DynaRetarget object success、carry progress ratio、transport success。
3. **Robot-side**：OmniRetarget contact preservation @ 5 cm、deep penetration duration、leg interference、foot skating、pelvis_z_min fall detection。
4. **Visual stability**：人眼复核在线 rollout 视频，独立给出 fall 标签和 push/leg shortcut 标签。

四层结果**必须分开汇报**，不能把第 2 层成功等同于完整成功。这是 E018b 的核心教训（详见 §5.3）：13/13 通过第 2 层 object 端的全部 gate，但 robot-side / visual 仍各有约一半 case 失败。[基于 `log/19:43-50`]

### 5.5 消融实验

**E013 oracle**：把 object 完全按 ref kinematic override 时 obj `0.011/0.038m`、xy `1.000`、rot `2.0°`、leg `0%`（`log/13`）。证明 ref 本身在 true freejoint 下完全可达，给后续所有 soft target 划了量化天花板。

**E015 dynamic support + PD**：升级到 COLA 完整 A+B 反而退化：default main obj `0.311/0.418m`、rot `50.3°`、PD force 打到 250 N clamp、2/3 main 数值不稳（`log/15:7-9`）。说明 **B 已经足够；引入 dynamic body + 主动 PD 不仅不带来收益，还引入了 partner-side compliance 调参困难和 solver 边界问题**。这条结论直接驳回了"COLA 越完整越好"的朴素假设。

**E016 anchor-from-mask 失败**：自动 anchor 用 `mask_active_palm_centroid_surface_clamp` 在 `box023_p2` 上把 face 选错（GT 在 +X、predicted 在 +Y），contact preservation 大幅下降（`log/16`、`log/17`）。E016 的失败凸显了 E018 canonical 规则的必要性：anchor 不能由 contact mask 单一证据驱动，必须用 audit + canonical fallback。

## 6. 讨论

### 6.1 object-side success ≠ 完整 retargeting 成功

E018b 13/13 在 object 端通过 SPIDER / DynaRetarget / transport / canonical anchor 全部 gate，但 strict generalization 只有 1/13。这是本工作最需要被诚实呈现的事实。13 个 case 里 5 个 contact preservation 不足、4 个机器人摔倒（pelvis_z_min 落到 0.13-0.44 m）、2 个 robot-side artifact、1 个 push/leg shortcut。原因主要在 reward 设计层面：当前 CEM 在 weld equality 存在时学到 "object 已被 weld 拽到 ref，hand 不必时刻贴紧"，这是 robot-side reward 没有反映 partner-physics 真实负担的副作用。4 个摔倒 case 同时暴露 spider framework 缺少 fall gate、leg collision penalty、partner-reaction force budget 这些 robot-side 安全约束。

E081 当年的 7.5% leg interference 已经被 leg-object collision pair 修正到 0%；但 fall / robot-side artifact 在 actuator-guided 模式下被 object actuator 暴力 mask 住了，到 true freejoint + COLA-B 才暴露出来。这恰恰说明 *真物理基线下评测能逼出隐藏问题*。

### 6.2 范式选择的几个反直觉教训

第一，spring 范式的 xy lag 是数学下限，不是参数没调好（`τ=√(m/k)` 推导 + E011 实测吻合，§4.2）；不要在 force 范式里继续做 sweep。第二，position constraint（weld equality）的关键不在 stiffness 多大，而在 anchor 是不是 partner-side / 非 COM —— anchor 设错会复现 E006 的旋转 shortcut。第三，COLA 完整范式 = B + A，但 B 已经足够好时加 A 反而退化（E015 vs E014），不要因为 "更完整 = 更好" 而盲目升级。

### 6.3 下一步

按方向 review v4 与 `plan/20-22`：

- **Robot-side stability**：fall gate（pelvis_z 与 root tilt 联合）、leg-object collision penalty、stance reward 加权（E022+）。
- **Contact 闭环**：重新审视 hold-contact reward 在 weld 存在下的有效性；或上游修正 contact mask 几何（E021/E022）。
- **Multi-agent partner**：bucket 类 case 单 G1 本质不可行（4/13 fall 中 2 个是 bucket），需要 dual-G1 协作建模。
- **RL prior 衔接**：把已经 work 的 case（`box025_p2`）导给 holosoma RL 做 residual policy 训练（`plan/22_E021_*.md`）。

## 7. 结论与未来工作

### 7.1 结论

在 CORE4D 真 freejoint + 双人协作设定上，**COLA-B soft-weld + canonical support proxy anchor 是首个做到 object 端跨 13 case 全部通过、且单 case object 精度逼近/超过单人 actuator-guided baseline 2× 的方案**。具体证据：(1) E014 在 `box025_p2` 上 obj `0.056/0.087m`，在更严苛 true-freejoint 设定下显著好于 E081 actuator-guided baseline `0.143/0.271m`；(2) E018 把 E014 手工 anchor 自动化成 face-center + 0.62·half_z 规则，两个 GT case anchor dist ≤ 1.17 cm 且 object tracking 与 E014 几乎逐位对齐；(3) E018b 把规则推广到 13 case，13/13 object-side / transport / SPIDER / DynaRetarget pass，2/2 GT anchor pass。

同时，本工作诚实揭示完整双人协作动力学重定向远未解决：robot-side stability（13 case 中 4 个摔倒、9/13 upright ok）、contact preservation（13 case 中 5/13 ok）、deep penetration（7/13 ok），这三块是后续 E020+ 的主攻方向。**object-only success 不等于完整 retargeting 成功**，是本工作给 community 的最重要的方法论提醒。

### 7.2 未来工作

- **修复 E018b 失败 case**：fall gate + leg collision penalty + contact-preservation reshaping（见 `plan/21_E020_*.md`）。
- **跨方法对比**：在同一 13-case 集合上跑 OmniRetarget kinematics-only 对照，量化"运动学 vs 物理"的真实差距（见 `plan/20_E019_*.md`）。
- **RL prior 端到端验证**：把 `box025_p2` 等 work case 喂给 holosoma residual RL pipeline，验证物理一致 retargeting 是否真能简化下游 RL 课程（见 `plan/22_E021_*.md`）。
- **Multi-agent partner**：bucket 类 case 单 G1 几何不可行，需要真正的 dual-G1 协作建模（全新方向）。
