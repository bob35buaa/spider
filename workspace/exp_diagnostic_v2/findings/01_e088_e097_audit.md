## Section 1 — 各实验单段总结

### E088 — 硬安全 gate + 绝对物体离地 reward
- **目的**：测试 diagnostic_report §4 — box021 D003 失败能否由 (a) 一个抛弃头/上身/物体穿模样本的硬 CEM elite-selection gate，加上 (b) 一个替换掉锚在 `ref_bottom`、已损坏的 `object_lift_rew/object_floor_penalty` 的绝对离地 reward 治好。
- **配置**：单 case `d003_box021_20231018_029_p2`，10 kg derived scene，3 个 full CEM 变体：A=仅 hard-gate，B=hard-gate + 降低 contact/object 权重，C=B + 绝对 clearance reward `clearance ∈ [0.04, 0.18] m`。
- **结果（出自 `110_E088_hard_safety_gate_lift_floor_results.md` §"主指标"）**：三者均 FAIL gate（`accepted_variants=[]`，见 `workspace/core4d/results/E088/e088_gate_summary.json`）。
  - A：contact 82.2%，head pen 27.9%，upper 55.0%，LH-floor 10.8%，`valid_frac=0.0029`（90.7% fallback）。
  - B：head 71.3%，upper 75.2%，`valid_frac=0`（92% fallback）。
  - C：head 19.4%，upper 80.6%，LH-floor 40.3%，clearance 均值 5.5 cm 但通过翻箱/趴箱实现。
- **结论**：瓶颈不在质量/权重/gate 阈值；绝对 clearance reward 机制正确但可被 hack；CEM 在当前 target 空间下找不到任何"手部受支撑且上身安全"的轨迹 → 转向"gate feasibility audit" + "anti-tip clearance gate"作为下一步。这直接推动了 E089 的数据侧干预。

### E089 — G1-Feasibility gate A+B 验证
- **目的**：通过两条路径验证 diagnostic_report 的 H1（"box021 D003 G1 wrist target 几何不可行"）：A = 使用已经几何可行的 `box021_person1` case（新 gate 预测 PASS）；B = 对 13 个 D003 box021 case 做 post-IK damped-LS wrist re-IK，把 wrist+5cm 投到世界向上的 box face。
- **配置**：A 路径：1 GPU full CEM on `box021_person1`，叠加 E088 hard-gate stack 与 `ref_fk` target。B 路径：subagent 重写 `trajectory_kinematic.npz`（waist 3 + arms 14 DoF MuJoCo damped-LS，约 25 iter/帧）→ 13 case 各派生 `_btop` 任务。B4：SPIDER 4-iter smoke on 按 composite-margin 评分的 top-2 case（`031_p2_btop`、`020_p1_btop`）。
- **结果（出自 `111_E089_g1_feasibility_AB_results.md` §§2,3,4）**：
  - A full CEM：contact 60.2%，obj_mean 1.3 cm，pelvis_min **0.687 m**，head/upper/LH-floor/RH-floor 全 **0.0%**。第一例同时满足三项安全归零的 box021。
  - B 13-case post-IK：L/R inside-box 从 ~3%/~6% 降到 0%/0%；world-up-face-frac 4%/14% → 99%/99%；wrist-below-pelvis gap ~0.25 m → ~0.16 m。
  - B4 smoke：head 0%/0%，upper 1.9%/0%，LH-floor 7.5%/0%，但 pelvis_min 仅 0.087–0.147 m（smoke-only；A 的 smoke 同样仅 0.19 m，full CEM 之前）。
  - 4/4 claim PASS。
- **结论**：G1-feasibility gate 是有效的数据侧 filter；reward/质量/hard-gate 都不再 binding；diagnostic_report 的 H1 被支持。已知 bug：gate 的 `top_face_frac` 硬编码 local `+z`，对旋转过的箱子严格给 0/13 — 语义 gate 给 9/13。

### E090 — H2-first retarget + topface-preIK ablation
- **目的**：拆解 OmniRetarget 哪一步真正驱动失败。测试 (i) 关掉 `--replace_wrist_with_fingertip`（no-fingertip）和 (ii) 真正的 pre-IK topface 投影 on `global_joint_positions[:, 20:22]`（即 `08_B_path_omniretarget_audit.md` 推荐的 B-1 路径）。

- **结果（出自 `112_E090…results.md` §§2,3）**：
  - no-fingertip：inside 0/0% 但 support 仅 17–27%，一例 CVXPY infeasible。Gate reject。

- **结论**：topface-preIK（B-1）是最强的单一几何修复；消除头/上身/手-地穿模；**但不能全局应用（破坏 Box025），且即使几何干净 pelvis collapse 仍存在**。C2（no-fingertip 改善 SPIDER）未触发；C3（原 Omni vs 当前）推迟。停止扩展 D003 13-case；下一步需要 pelvis/upright posture gate。

### E093 — Contact target 几何审计
- **目的**：在 7 个已知 case 上量化当前 reward target `ref_fk wrist_yaw_link + 5 cm`、raw CORE4D contact point、G1-sphere collision proxy、历史 HDMI 3-box proxy、handbox proxy 五者之间的真实失配。
- **配置**：6000+ 样本审计覆盖 `box023_p2, box025_p2, box004_083_p2, box021_person1, box021_d003_029_p2, box026_039_p2, box026_135_p2`。MuJoCo `--camera auto` 全身 render（用户指出仅可见上身后修正）。
- **结果（出自 `115_E093…results.md` §"关键指标"）**：
  - `wrist+5cm → raw mean` 在所有 14 行 per-hand 上 ≥ 20 cm；Box026/Box025 达到 49–64 cm。
  - Sphere-surface p90 gap 处处 > 10 cm，Box026/Box025 45–61 cm。
  - Handbox 是 14/14 的最佳 proxy 但 p90 仍 16–59 cm。
  - box023/box004 work 因为绝对 offset 落在 G1 可达范围且无 inside；box021_d003 fail 因为 R-inside 33% + 低 support + 选错面 + offset 组合。
- **结论**：在任何后续 CEM/RL 之前 target 语义修复是必须的；不要只换 sphere↔handbox。Box026 需要特别处理修复。计划：构造 E094 G1-handbox-aware target 投影。

### E094 — adaptive_support target 投影 + full CEM

  - Full CEM C1 box004：61.0% contact，pelvis 0.658 m，安全 0% → WORK（仅 2/210 hand-frame 被修改；实质与 E092 等价）。
  - C2 box026_039：contact 80.5%，obj_mean 0.002 m，pelvis **0.440 m** → 在 posture 上 FAIL（视觉上机器人趴在箱上）。

- **结论**：target 语义层已干净解决；全身 posture/dynamics 是新瓶颈。C1 已 RL-ready；Box026 需要单独 posture/upright gate，而不是更多 target 修复。

### 3.11 E090 topface-preIK 在 box021/Box025 失败的几何解释
- 之前 audit 写"global 全应用打破 Box025"是事后总结。新的因果解释：
  - box021 18029_p2 `obj quat = 90° around +X`（v1 §3.2）；half-extents (0.16, 0.21, **0.265**)。
  - 旋转后：**local +z → world −y（水平方向）；local +y → world +z（向上）**。
  - 02_face_selection_audit.md §3 B1 实测表里 box021 R wrist"true top face = local +z"是按 object local frame 投票出的"主接触面"，在世界里其实对应某个**水平长侧面**，不是顶面。
  - v1 §6 推荐的"投到 box top + 5 cm"以及 E090 实施的 topface-preIK，把 contact target 强行搬到了世界 +z 方向（即 box 的 local +y 顶面），**对 box021 是反着推**。
  - 这正好解释 E090 失败模式："S1 full 几何安全全 0% 但 pelvis 0.134 m" — 因为 IK 把 G1 推到"伸手到箱子上方按"，而 ref motion 是"蹲箱旁按侧面"，姿态根本对不上；剩下的 reward 又必须跟 ref motion，pelvis 只能往下塌。
  - 同时也解释 Box025 反退化：Box025 是侧抓（grip 60 cm 高凳上的箱子侧壁），world-up 投影把目标搬到顶面，IK 当然不可行 (`inside 48.1/51.9%`)。
- **结论**：world-up = top 假设只对 quat ≈ identity 的对象成立。box021（quat 90° X）与 Box025（侧抓 intent）都不成立；任何"全局 topface"或"per-object 默认顶面"的策略都要先做 quat-aware 的面选择。

## Section 5 — Top 重点结论

1. **几何是必要的，但不充分。** E089A 证明在几何可行的 box021 case 上同样 reward stack 可工作（pelvis 0.687 m、安全全 0%）。E090/E091/E094 接着显示即便几何/target 修复，全身 posture（pelvis collapse、Box026"趴箱"、D003 box021 RH-floor）是 diagnostic_report H1 未预料到的独立失败模式。

2. **diagnostic_report 计划在 `18029_p2` 上的干净 A/B（B2/B3 → C1）从未执行**；实际发生的是 case 替换（E089A 切到 `box021_person1`）加方法替换（B-2 lite 取代 B-1 OmniRetarget 重跑）。"H1 verified"主张方向正确但混杂；我们仍欠一次同 case 外部 target swap 才能真正闭环。

3. **box004 是唯一稳健的正例集合**（083_p2/083_p1/082_p1，由 E092/E094/E096/E096b 确认） — Box026 metric 在 target 修复下改善但掩盖了"趴箱"无效行为，整个 D003 box021 13-case 池在任何已测组合下都没有 SPIDER-WORK case。新挖掘（E097）在 legacy-outcome 过滤后找到零 unverified candidate，所以下一步进展取决于 Box022 preflight 或 holosoma inventory 扩张。

4. **E093 的 wrist+5cm 偏差不是 target source 调参问题，而是接触语义在 wrist 这一层就已经丢失**：mocap 5 指尖在 SMPL-X 22-joint 标准中被丢、`--include_fingertip_centers` 在 D003 production 关闭、G1 的 rubber_hand 又是无 DoF 球 — 整条 pipeline 没有任何位置真正代表"指尖在哪儿"。修复方向是在 OmniRetarget 输入侧补 fingertip 信息（开启 `--include_fingertip_centers` + core4d_v2），而不是在 SPIDER reward 端继续摇 wrist offset。这同时也是把 H1 与 H3 干净分离的前置条件（见 4.11）。
