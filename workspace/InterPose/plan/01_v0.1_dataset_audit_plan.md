## 📋 Context

CORE4D 已具备从原始动捕到 OmniRetarget、target gate、候选 handoff 和
CEM/RL evidence 的 `data_construction_v3` 链路。本实验审计本地 InterPose
数据与官方开源代码，只保留“双人共同作用于同一物体”的人-物-人三元关系，
并判断这些数据能否接入 SPIDER。

### 范围

- 纳入：本地实际存在的数据、论文中明确给出的数据定义、官方代码可验证的
  schema，以及可由字段或几何证据识别的人-物-人候选
- 排除：单人 HOI、纯人与人交互、没有共享物体轨迹的多人同框，以及未经
  证据支持的“协作”推断
- 本轮不运行训练、CEM 或完整重定向；只做只读审计、可复现统计和适配设计

## ✅ 成功标准

1. 统计脚本默认只读，路径通过 CLI 参数传入，输出可复跑
2. 文档区分“论文宣称”“本地观测”“代码推断”，不混用统计口径
3. 每个序列都能落到 `TARGET_HOH`、`NON_TARGET` 或 `UNRESOLVED`，并带理由
4. `data_stat.md` 至少给出动作/序列数、双人数量、目标候选数、物体类别、
   帧数/时长可得性、缺失字段与数据质量风险
5. `adaptation_plan.md` 明确工作区布局、阶段、产物、验证 gate、registry
   轴、template/mesh 策略、retarget 路线及 CEM/RL handoff 边界
6. Python 编译、统计结果一致性断言、Markdown 链接检查、`git diff --check`
   全部通过

## ⚠️ 失败预演

| 失败方式 | 预防措施 |
| --- | --- |
| 把多人同框误作共享物体协作 | 要求同一 object identity/trajectory，并记录证据字段 |
| 用论文总量冒充本地实际量 | 论文与本地统计分表报告 |
| 文件名启发式造成错误类别 | 优先读 schema/metadata，启发式只作低置信候选 |
| 直接套用 CORE4D template | 先审计 InterPose 物体几何、尺度与坐标系 |
| 过早宣称可用于物理执行 | S2–S4 gate 通过前只标记 candidate，不标记 release |
